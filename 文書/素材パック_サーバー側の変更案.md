# 素材パック: サーバー側（DaiDaiリポジトリ）の変更案

2026-11-26。**案です。DaiDaiリポジトリは編集していません。** HomePage-Rhingの手順①（投稿画面と機械の検査、ブラウザの中で完結）は実装済みで、手順②以降が、この案の対象です。依頼文は`DaiDai-private/文書/検討/素材パック_横丁用プロンプト.md`。設計の一次情報は`DaiDai/文書/検討/素材パック.md`。

## 前提（既存のぺったんパックを調べて分かった事）
- ぺったんパックには、**審査フローが無い**。`createStickerPack`は、作成の瞬間に`stickerPacks`へ公開する。`status`も無い。審査の状態遷移は、素材パックで新設する。
- `stickerPacks`は、誰でも読める（`read: true`）。**未承認のパックを、同じコレクションに混ぜてはいけない。** 別のコレクションにする。
- ぺったんは、画像を**ダウンロードURL**で保存している。素材パックは、方針どおり**保存先のパス**で持ち、表示時に解決する。クライアントに、パスからURLへの共通ヘルパーが無いので、新設する。
- Storageのルールは、`contentType`と`size`しか見られない。zipの中身は見られない。**検査は、Functionsで再度行う**（ブラウザの検査は、投稿者への案内で、信頼の根拠にはしない）。
- 管理者は、IDトークンの`admin === true`（`assertAdmin`、ルールの`isAdmin()`）。監査ログは`writeAdminAuditLog`で、`action`は文字列の共用体。
- 通知は、メールを使わない。入手者向けには、`users/{uid}/notices`の個別お知らせと、FCMのプッシュが有る。**出品者向けの通知は、無い。**

## 1. データの置き場（案）
| 場所 | 中身 | 読み取り | 書き込み |
|---|---|---|---|
| `themePacks/{packId}` | 公開中の素材パック。`name`・`creatorId`・`brightness`・`version`・`assetPath`（保存先のパス）・`status`（`approved`のみ）・`createdAt`・`approvedAt`・`ownerCount` | 誰でも | Functionsのみ |
| `themePackSubmissions/{submissionId}` | 投稿（審査中・差し戻し・取り下げ・配信停止も含む）。`packId`・`creatorId`・`version`・`status`・`assetPath`・`decisionNote`・`decidedBy`・`decidedAt`・`rightsAcceptedAt` | 投稿者本人と管理者 | Functionsのみ |
| `users/{uid}/ownedThemePacks/{packId}` | 取得済みの記録（`{packId, grantedAt, version}`）。ぺったんの`ownedStickerPacks`に倣う。**混ぜず、別にする** | 本人 | Functionsのみ |

- パックのidは、投稿者ごとの名前空間にする（`{creatorId}__{id}`など）。pack.jsonの`id`は、ディレクトリ名とも一致させる必要が有り、他の投稿者と衝突し得るため。
- 状態: `submitted`（検査済み・提出）→ `inReview`（審査中）→ `approved` / `rejected`（差し戻し、理由つき）。公開後は、`withdrawn`（投稿者が取り下げ）、`suspended`（権利侵害などの配信停止）。**非公開の試用**は、`submitted`の間、投稿者本人だけが読める経路で行う。
- 同じidでの再投稿は、新しい`version`の投稿として別の`submission`を作る。承認されるまで、公開中の旧版は、そのまま公開する。1人5件まで（公開中と審査中の合計）。

## 2. 保存先（Storage、案）
- 投稿の素材: `themePackSubmissions/{creatorId}/{submissionId}/…`（`pack.json`と背景画像）。**投稿者本人と管理者だけが読める**。作成は、投稿者本人だけ。サイズ・`contentType`は、ルールで制限（画像は2MB以下、png/webp/jpeg）。
- 公開の素材: `themePacks/{packId}/{version}/…`。承認の時に、Functionsが投稿の場所から**コピー**する（`get`は誰でも可、`list`は管理者だけ。`contactAttachments`の先例）。投稿の場所を読み取り専用のまま残すと、差し戻しや再提出の履歴にも使える。
- Firestoreには、パス（`themePacks/{packId}/{version}`のような接頭辞）だけを持つ。URLは持たない。表示時に、ヘルパー（`getDownloadURL(ref(storage, path))`）で解決する。
- 試用: アプリの`ThemePackRepository`（DaiDai側のセッションで実装）が、投稿者本人のログイン状態で、`themePackSubmissions/{creatorId}/…`を読める。一覧の取得口は、`themePackSubmissions`を`creatorId == 自分`で引く。

## 3. Cloud Functions（案。region `asia-northeast1`）
| 関数 | 認可 | 主な処理 |
|---|---|---|
| `submitThemePack` | 要ログイン | 投稿の素材（Storage）を**サーバーで再検査**（zipの目録・展開後の大きさ・`pack.json`・画像のヘッダーと大きさ・コントラスト、3:1以上）。`ThemePackParser`と同じ規則を、`functions/src/themePack.ts`にTypeScriptで持つ（HomePageの`src/lib/themePack/`と、規則・上限・テスト入力を揃える）。投稿数（5件）と`creatorProfiles`の作成も行う。`rightsAcceptedAt`を記録 |
| `approveThemePack` | `assertAdmin` | 審査待ち→承認。素材を公開側へコピーし、`themePacks`へ作成または更新。出品者へ通知。監査ログ |
| `rejectThemePack` | `assertAdmin` | 差し戻し。理由（必須）を`decisionNote`に。出品者へ通知。監査ログ |
| `withdrawThemePack` | 投稿者本人 | 取り下げ。`themePacks`を新規取得の対象から外す。**取得済みの人は、使い続けられる** |
| `suspendThemePack` | `assertAdmin` | 配信停止（権利侵害）。素材を非公開にし、取得した人の画面を**標準へ戻す**。有料なら返金（最初の公開は無料のみ） |
| `acquireThemePack` | 要ログイン | 無料の取得。`ownedThemePacks`へ記録し、`ownerCount`を増やす（`grantOwnership`に倣う）。`status != approved`は拒否 |
| `uninstallThemePack` | 本人 | 取得済みの記録を外す |

- 監査ログの`action`に、`approveThemePack`・`rejectThemePack`・`suspendThemePack`を追加。
- 価格は、後から足せるように、`themePacks`に`price`（整数、0が無料）を**持てる構造**にしておく（今は常に0。`PAID_PACKS_ENABLED=false`の間は、有料を拒否）。
- 「取り下げ」と「配信停止」で、取得済みの人の扱いが違う。`ownedThemePacks`の`version`と`themePacks`の`status`を、アプリが見て、停止なら標準へ戻す（DaiDai側のセッションの作業）。

## 4. セキュリティルール（案、Firestore）
- `themePacks`: `read: true`、`write: false`（`status == 'approved'`のものだけを置く）。
- `themePackSubmissions`: `read: 本人（`creatorId == request.auth.uid`）または管理者`、`write: false`。
- `users/{uid}/ownedThemePacks`: `read: 本人`、`write: false`。
- collectionGroupの逆引き（`ownedThemePacks`を`packId`で）には、`firestore.indexes.json`のfieldOverrideが要る（`ownedStickerPacks`の例）。

## 5. 通知（案、メールは使わない）
- **出品者へ**（承認・差し戻し）: `users/{creatorId}/notices`に個別お知らせを入れる（`kind: "themePackReview"`）。あわせて、creatorページ（HomePage）で、投稿の状態と、差し戻し理由を見せる。FCMのプッシュも、既存の`notifyPackOwners`と同じ作りで送れる。
- **取得者へ**（配信停止）: 既存の`notifyPackOwners`を一般化するか、素材パック用に複製する。

## 6. HomePage側（手順②以降、このリポジトリ）
- 投稿の送信（検査に通ったzipを、Storageの`themePackSubmissions`へ置き、`submitThemePack`を呼ぶ）。
- 非公開の試用の導線、審査画面（`admin`配下。`AdminClient`の作法に倣う）、公開の一覧と詳細、取得ボタン、取り下げ。
- メニュー（`DaidaiYokochoMenu`）と、creatorページへの入口。
- ストア版のiOSアプリから、横丁へのリンクを出さない既存の方針（`yokochoLinksAllowed`、DaiDai側）は、変えない。
