# /daidaicheck

呼び出されたら、以下を順に行う。

## 1. チェックリストを読む

- `/home/arata/Rhing/Applications/DaiDai/実装内容チェックリスト.md`を絶対パスで直接読む。DaiDai本体は別リポジトリなので、このファイルの読み取り以外の操作（git操作等）はしない。
- `[ ]`（未実装）項目のうち、直後に`**[近日]**`/`**[将来]**`/`**[検討中]**`/`**[不採用]**`のいずれかのタグが付いているものだけを対象にする。タグ無しの`[ ]`項目（バグ調査・実機検証待ちなど）は、チェックリスト自身の運用ルール上も「意思決定の対象ではない」内部向けの注記なので対象外とする。
- 同一の機能が複数セクション（「2026-09-08優先度整理」「課題.md記載の未解決事項」等）に重複して登場することがあるため、機能単位でまとめて1件に集約する。

## 2. 一般ユーザー向けの文章に書き直す

- 各項目を、開発者向けの専門用語・ファイルパス・関数名・日付を含まない、1行程度の簡潔な日本語に書き直す。
- `src/app/services/daidai/`配下の既存の文章（ヒーローのコピー、`pillars`や`moreFeatures`の説明文など）と同じトーンに合わせる。

## 3. `src/app/services/daidai/AudienceContent.tsx`を更新する

- `GeneralContent()`内の`id="future"`セクション（見出し「今後追加予定」）にあるデータ配列（`featureRoadmap`・`notPlannedFeatures`）の中身を、最新の集計結果に丸ごと置き換える。
  - `近日`/`将来`/`検討中`タグの項目 → `featureRoadmap`（機能名＋状況）
  - `不採用`タグの項目 → `notPlannedFeatures`（「実装しない機能」の簡潔なリスト）
- 見出し文言・`id="future"`・`generalContents`のナビ項目・テーブルや配列の型定義・スタイリング（既存のクラス構成）はそのまま維持し、配列の中身だけを差し替える。`pillars`・`moreFeatures`など他のデータや`GeekContent()`側は変更しない。
- 現在の内容と比べて変化が無い場合は、無駄な差分を作らない（ファイルを書き換えない）。

## 4. 検証・報告

- `npx tsc --noEmit`と`npx eslint src/app/services/daidai/AudienceContent.tsx`でエラーが無いことを確認する。
- 機能単位で何が追加・削除・変更されたかを日本語で報告する。
- **コミット・pushは行わない**。このリポジトリのCLAUDE.mdの通常ルール（通常のコード変更のpushは都度確認を取る）に従い、コミットするかどうかはユーザーの指示を待つ。
