# /diary

呼び出されたら、以下を順に行う。

## 1. 今日の作業内容を集める

- `git log --since=midnight --oneline`（または当日分のコミット）と `git status` / `git diff` で、今日行った実装・変更点を把握する。
- コミットされていない作業も対象に含める。
- 今回の会話の中で発生した詰まりどころ（エラー、設計判断で迷った点、原因調査に時間がかかった点など）を振り返る。特に詰まりがなければ正直に「特になし」と書く。捏造しない。
- TodoWriteのタスクリストや会話の流れから、次にやるべき具体的な項目を洗い出す。

## 2. 日記.mdに追記する

- 場所: リポジトリルート（`/home/arata/Rhing/HomePage/日記.md`）。
- ファイルが無ければ新規作成。あれば**新しいエントリを先頭に追記**（新しい日付が上に来る形）。
- 1エントリのフォーマット:

```markdown
## YYYY-MM-DD

### 実装内容
- ...

### 詰まったところ
- ...（無ければ「特になし」）

### 次にやること
- ...
```

- 同じ日に複数回 `/diary` が呼ばれた場合は、その日のエントリに追記・統合する（同日で見出しを重複させない）。
- 内容は今日の会話・git履歴から確認できる具体的な事実のみ書く。推測や一般論で埋めない。

## 3. 先頭のTODOリストを更新する

- 日記.mdの一番上（最初の`## YYYY-MM-DD`エントリより前）に、日付をまたいで持ち越す`## TODOリスト`セクションを1つだけ持つ。無ければこの時点で新規作成する。
- フォーマット:

```markdown
## TODOリスト
- [ ] 項目A
- [ ] 項目B
```

- 更新手順:
  1. 現在のTodoWriteタスクリスト（未完了・進行中の項目）と、会話から洗い出した「次にやるべき具体的な項目」を集める。
  2. 既存のTODOリストと突き合わせ、今回の会話やgit履歴（コミット・デプロイ等）から完了が確認できた項目は**リストから削除する**（消し込む。取り消し線や`[x]`のまま残さず、単純に行ごと消す）。
  3. まだ既存リストに無い新規の未完了項目を追加する（同じ内容の重複追加はしない）。
  4. 結果として残るのは「現時点で未完了の項目」のみにする。全て完了していればリストは空（`## TODOリスト`の見出しの下に項目なし）でよい。
- 各日のエントリの「次にやること」は、その日の作業から見えた次の一手を書く一覧（日々のスナップショット）。TODOリストは日をまたいで残る唯一のバックログという役割分担を維持する。両者の内容が重なることはあるが、削除・統合の対象になるのはTODOリストの方だけで、過去日の「次にやること」は書き換えない。

## 4. コミット・push

日記.mdおよびNext.js/Reactプロジェクト一式（`src/`, `public/`, `package.json`, `next.config.ts`, `tailwind.config.ts`, `tsconfig.json`等、リポジトリ内の変更全般）の更新は事前承認済みの操作。確認を取らずに以下を実行する。

```bash
git add -A
git commit -m "日記: YYYY-MM-DD"
git push
```

- upstreamが未設定の場合は `git push -u origin main`（または現在のブランチ）で設定する。
- `git add -A`する前に`git status`で内容をざっと確認し、`.gitignore`で想定通り除外されているか（`node_modules/`, `.next/`など）だけ確認する。**このリポジトリはdaidai横丁関連の実装でStripeのシークレットキーやFirebaseのサービスアカウント鍵を扱うため、`.env`・`.env.local`・`.env*.local`・`service-account*.json`・`*.pem`・`*-key.json`など、シークレットらしきファイルが`git status`の一覧に紛れ込んでいないかを必ず個別に目視確認する。** 少しでも心当たりのない、または鍵・トークンらしき内容を含む不審なファイルがあれば、絶対にコミットせずユーザーに報告して指示を仰ぐ。
- pushが失敗した場合（コンフリクト、リモート未到達など）は、force pushなどで無理に解決せず、状況をユーザーに報告する。
