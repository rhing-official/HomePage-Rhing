# /server

呼び出されたら、以下を順に行う。この一連の操作はローカル環境内で完結し、外部への影響が無いため、確認なしで実行してよい。

## 1. 依存関係の確認

- `node_modules/`が存在しない場合は`npm install`を実行する。
- 存在する場合でも`package-lock.json`が`node_modules/`より新しく更新されている等、明らかに不整合が疑われる場合はユーザーに`npm install`し直すか確認する。

## 2. 既存のサーバーを必ず止める（強制再起動）

起動中かどうかに関わらず、**常に再起動する**。既に動いていても、そのURLを案内して終わらせず、止めてから起動し直す。

- このプロジェクトの`next dev`だけを止める。他のプロジェクトのプロセスや、ポート3000を使っている無関係なプロセスは止めない。
  - 例: `pkill -f "/home/arata/Rhing/HomePage/node_modules/.bin/[n]ext"`（親の`sh -c next dev`は、子が終わると一緒に終わる）。**`[n]`の形にする**: そうしないと、実行中のシェルのコマンド行にもパターンが一致して、自分のシェルごと止まる。
  - 止められたか、`ps aux | grep "[n]ext dev"`と`lsof -i :3001`で確認する。残っていれば、数秒待って再度確認し、それでも残るときだけ`kill -9`で止める。
- 前回の起動が異常終了していて`.next/dev/lock`が残っているときは、削除してから起動する。
- 画像や設定を更新した直後などで表示が古いときは、`.next`を消す必要はない（ユーザーが求めたときだけ消す）。

## 3. 開発サーバーを起動

- リポジトリルートで、ログを`/tmp/homepage-dev.log`に書き出しながら`npm run dev`をバックグラウンド実行する(`npm run dev > /tmp/homepage-dev.log 2>&1`を、Bashツールの`run_in_background: true`で実行する。`/hotrestart`がこのログを読む)。
- 起動直後の`/tmp/homepage-dev.log`を数秒〜十数秒待って確認し、"Ready"等の起動完了メッセージと実際に待ち受けているポート番号を把握する。
- 起動失敗(エラーで終了、ポート競合が解決できない等)の場合はログの内容をそのままユーザーに提示する。

## 4. 結果報告

- 実際に使われたURL(例: `http://localhost:3001`)をユーザーに伝える。再起動した場合は、その旨（以前のサーバーを止めて起動し直したこと）も一言添える。
- 停止したい場合はバックグラウンドタスクを止めればよい旨を一言添える。
